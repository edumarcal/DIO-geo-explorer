# Desafio: Geo-Explorer

## Contexto

Agora é a sua hora de praticar, aprender fazendo e construir um projeto para o seu portfólio.

Neste desafio, você vai criar o projeto **Geo-Explorer**, uma solução que ajuda a pessoa usuária a explorar trilhas de aprendizagem, receber desafios de código e gerar um certificado fictício ao concluir uma rota de estudo.

A ideia é combinar dados fictícios, comandos inteligentes e documentação clara em um projeto funcional, útil e bem estruturado.

## Objetivo

Você deve desenvolver uma aplicação que permita:

- consultar trilhas de estudo por tecnologia;
- receber um desafio de código com base na tecnologia e no nível solicitado;
- gerar um certificado fictício ao concluir uma trilha;
- testar o comportamento dos comandos e documentar como o projeto funciona.

Além disso, a solução deve ser pensada para evoluir e se conectar com ferramentas externas por meio de um servidor MCP.

## O que será entregue

O projeto deve incluir, no mínimo, os seguintes componentes:

1. Base de dados fictícia de trilhas
   - tecnologias;
   - níveis de dificuldade;
   - módulos/etapas de conteúdo;
   - descrição das trilhas.

2. Comando de trilha
   - recebe uma tecnologia;
   - exibe uma trilha de estudo organizada;
   - inclui objetivos, módulos e próximos passos.

3. Comando de desafio
   - recebe uma tecnologia e um nível;
   - gera um desafio de código relacionado ao tema;
   - pode incluir instruções, critérios de aceitação ou sugestões de solução.

4. Comando de certificado
   - recebe os dados da trilha concluída;
   - gera um certificado fictício com nome, tecnologia, conclusão e assinatura.

5. Testes automatizados
   - validam o funcionamento dos comandos;
   - garantem que os dados gerados atendem ao esperado.

6. Documentação
   - README com descrição do projeto;
   - instruções de execução;
   - exemplos de uso;
   - como rodar os testes;
   - melhorias e aprendizados.

## Requisitos técnicos

- Estruture o projeto em pastas e módulos organizados;
- Use uma base de dados fictícia em arquivos localmente;
- Crie funções ou comandos reutilizáveis;
- Documente o fluxo principal da aplicação;
- Inclua testes para validar os resultados;
- Publique o projeto em um repositório no GitHub.

## Entregáveis

Ao final, você deve publicar sua versão do projeto em GitHub e incluir em seu README:

- o que é o Geo-Explorer;
- como executar o projeto;
- como usar os comandos;
- como executar os testes;
- quais melhorias foram realizadas;
- o que você aprendeu ao desenvolver a solução.

Antes de publicar, revise os arquivos gerados e nunca envie senhas, tokens ou informações privadas para o GitHub.

## Critérios de avaliação

Seu projeto será avaliado pela qualidade e pela clareza de sua implementação. Os pontos principais são:

- organização do código;
- funcionalidade dos três comandos principais;
- qualidade dos dados de trilhas;
- presença de testes automatizados;
- documentação clara e objetiva;
- criatividade e melhorias extras.

## Sugestões de evolução

Depois de concluir o fluxo principal, você pode ampliar a solução com ideias como:

- novas trilhas e tecnologias;
- tipos diferentes de desafios;
- template de certificado mais sofisticado;
- novos comandos extras;
- interface visual;
- integração com outras ferramentas ou APIs;
- adaptação do tema para outro contexto.
